How Highlights work: the whole picture

Brainstorm, 2026-11-28 · For Miky. Nothing here is decided by this page; it draws what the Accepted records already say as one system, and marks what is still open.

A highlight is something worth keeping from the work: what we learned, what we decided, what happened, what worries us. Each is kept as a file of its own, which people read in their apps and which AI reads as memory. Updates and Decisions are the first two words of it to be built. This page draws the whole, so the first slice is cut from the right shape. Read the Map, then the one open shape question under Objects.

Objects: what a highlight is

The open shape question: one type with a word, or a type per word

The records say three shared types (Insight, Journal entry, Risk), each word a field inside its type. A file's type is written once, on its first record, and never changes. So under today's records a Decision can become an Update (a field), but a Highlight cannot become an Insight, and a Question cannot become a Decision: each is a new file that points at the old one. This decides the first slice, because the first Journal entry written fixes it.

Scope: team highlights and personal highlights

For the first slice this means: a Claude session's entry is filed in the project's team and read by that team. The session may know things from your other teams and your notes, so the warning before it writes into a wider place belongs to the recording command from day one.

What an agent actually reads is the brief: a text written from a place's highlights, with the highlights as its sources a person can open and correct. So the chain is: work → highlights → brief → the next session. The first slice builds the first link for sessions (they write highlights). The last link (they start from the brief) is what makes it memory.
