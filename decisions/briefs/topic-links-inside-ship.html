When you click a link to a topic inside Ship, do you stay in Ship?

Brief for Miky · 3 Nov 2026 · from the kickoff of "A topic's page in Ship"

The question

Ship is getting its own page for a topic. When someone has written a link to a topic in an issue's description or a comment — the link is Peek's address, because that is what you copy from Peek — should clicking it inside Ship open Ship's page for that topic, or Peek, as the address says?

Today

On 20 Oct you decided: a link opens as written, in the app its address names, and every app answers every app's address on its own host. So in Ship, a link to peek.estiva.app/topic/… opens Peek, and a link to leaf.estiva.app/issue/… opens Leaf, not Ship's issue page.

On 2 Nov, shaping this project, you decided: every topic link inside Ship opens Ship's topic page, in a description or comment too; Leaf's topic links still open Peek. The two calls disagree on one case only: a topic link someone wrote. The "Topics: …" line, the Topics page and a topic Ship draws itself are not written links, so they open Ship's page whatever you pick here.

Why it reaches beyond this ticket

It is the click rule every app follows, Peek, Leaf and an outside company's app included, so it goes in the Specification. Nothing is written to the relay: links in old messages stay as they are and only where a click lands changes. Two-way door, but undoing it means a release of every app that follows it.

The obvious rule, "stay in the app you are in whenever it can show the file", fails: Peek can show every file as a conversation, so every Ship issue link in Peek would open a Peek conversation instead of the issue, and an outside app's links would never reach that app from Peek or Leaf. A working rule has to tell a page made for that kind of file from a general view of every file.

Options

A · Do less: a written link opens as written (the 20 Oct rule stands)

The "Topics: …" line and the Topics page open Ship's topic page; a topic link someone wrote in a description opens Peek. What could go wrong: one screen, two outcomes — the same topic opens Ship from the Topics line and Peek from the sentence above it, which is the "every click leaves Ship" you wanted gone. Part of your 2 Nov call is dropped.

B · Stay in the app you are in whenever it can show the file

Simple to say. What could go wrong: Peek shows every file as a conversation and Leaf every file as a page, so Ship's issue links in Peek open Peek, in Leaf open Leaf, and an outside app is never reached from either. A link to one message lands on a topic page that cannot show it.

C · Stay only when the app you are in has a page made for that kind of file, and it can show what the link points at (recommended)

In Ship, a topic link opens Ship's topic page; a link to one message in a topic still opens Peek, on that message; a Ship issue written with Leaf's address opens Ship's issue page (today it opens Leaf). Peek keeps opening topics itself. In Leaf nothing changes: Leaf's page for an issue is its general page for every file, not one made for issues, so Ship links still open Ship. What could go wrong: it is one more rule an outside app must apply about itself ("do I have a page made for this kind?"); an app that wrongly says yes keeps people from the file's own app. Each app decides this about itself and never declares it, so no app's manifest lists another's types (you rejected that list on 20 Oct).

How others do it

  • Slack / Linear: a Linear link in Slack unfurls in Slack but opens Linear; Linear opens its own issue links in Linear. That is C: the app with a page made for the thing keeps it.
  • Google Workspace: a Docs link in Gmail opens Docs, never a Gmail view of the doc — A for apps without their own page.

Recommendation

C. It keeps what the 20 Oct rule is for — an address names one file whatever the host, and a link to one block or message lands on it — and it gives you what you asked on 2 Nov: while you browse work in Ship, a topic opens in Ship. The host names the perspective; when you are already in a perspective made for that kind of file, that is the one you chose. A topic is a file no app owns (Peek opens it because it shows every file's conversation), so the rule cannot be "the owner's app"; it has to be "a page made for that kind".
