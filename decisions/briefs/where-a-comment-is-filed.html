Who can read a comment on a private file

A decision brief for Miky · 19 October 2026 · Leaf edits any file's text (found in the security review)

The question. Once a Folder can be private, should a comment on one of its files be readable by exactly the people who can read the file, even when that file is also shown in a Folder everyone can open?

Today

A file lives in one Folder, and that Folder decides who can read it. It can also be shown in another Folder (that's what a move does). Being shown there gives nobody access. On 2 October you decided that a file's conversation is everything about it, whichever Folder each comment was stored in, and that new comments are stored in the Folder that shows the file. Today's spec says the same for every app, including Leaf.

A comment is stored in a Folder too, and that Folder decides who reads the comment. So the 2 October rule means a comment's readers are the showing Folder's members, not the file's. Today it makes no difference. Every Folder is open to the whole workspace, so both groups are the same people. It starts to matter on the first day a Folder can be private.

Why it reaches beyond this ticket

This sets the rule for every app that writes a comment, Leaf, Peek and Ship and also an outside company's: who reads a comment. A company adopting Nostr-for-Business would expect a comment on a private document to be as private as the document. Google Docs, Notion and Linear all work that way.

It's a two-way door until private Folders ship, then one-way. A comment's storage Folder is fixed when it's written. Once comments about private files sit in open Folders, they've been readable there, and moving them later doesn't take that back. Private Folders are already a planned project (their listing has to be hidden first), so this is the moment to settle it.

Options

A · Keep the 2 October rule, and never show a private file in another Folder

A comment still goes to the Folder you opened the file from. To keep that safe, a file in a private Folder can't be shown anywhere else. Today the apps already refuse the opposite move: an open file can't be shown in a private Folder, because it would look private and not be.

What you'd see: in "Pricing", "Move to Everyone" isn't offered for the price draft. A link to it in a message still works for members.
Outside company: one rule to follow (comments go where the file is shown), plus a move rule.
Locks in: making an open Folder private later strands its files' old comments in other Folders. Either that switch is refused, or old comments stay readable.

B · A comment is stored with its file, always (recommended)

A new comment goes to the Folder that owns the file, whichever Folder it was opened from. Its readers are always the file's readers, whatever the Folders' settings are or become. Reading doesn't change, because the conversation is still everything about the file, wherever it's stored.

What you'd see: nothing different on the file. A private file can still be shown in "Everyone", where non-members see a locked entry, and its conversation stays private.
Outside company: the simplest rule: a comment is filed with what it's about. It holds unchanged if access later moves from Folders to the file itself (the parked "Folders are labels" question).
Locks in: it replaces one line of the 2 October decision, where a new comment is stored. That decision's reading rule stays.

C · Showing Folder when it's open, the file's Folder when the file is private

Each app checks at write time: if the file's own Folder is private, the comment goes there; otherwise it goes where the file is shown.

What you'd see: the same as B for private files. For open files, the same as today.
Outside company: must read Folder settings before every comment, and two apps can disagree if one reads stale settings.
Locks in: it's only correct at the moment of writing. If "Pricing" was open when Miky commented from "Everyone" and turns private later, his comment stays readable by everyone.

How others do it

  • Google Drive / Docs: comments are part of the document, and anyone who can't open the doc can't read them, whatever folder shortcuts point at it.
  • Notion: comments inherit the page's permissions. A linked view in another workspace area shows nothing to people without access.
  • Slack: a message shared into another channel keeps its original channel's access. People outside see "message unavailable".
  • Upstream Nostr (NIP-22 comments, NIP-29 groups): a comment in a group is readable by that group. Nothing ties it to the file's group, so the protocol has to say which group.

Recommendation

B: a comment is stored with its file. A comment is part of the file it's about, so its readers should be the file's readers, decided once and never by where somebody happened to open it. It's the only option that stays right when a Folder changes from open to private, and when access later moves onto the file itself. An outside company follows one sentence. It keeps your 2 October call that a conversation is read by what it's about, and changes only where a new comment is stored.

Checked

  • No Folder is private today. On the relay, 49 Folders, 0 marked private (the one private group is a direct message). Read as the agent, 19 Oct.
  • 33 of 112 files are shown in a Folder other than their own, all between open Folders. So under today's rule some comments are already stored away from their file, and none of them is readable by anyone who couldn't read the file. Same read.
  • Private Folders aren't offered until their listing can be hidden from non-members (spec §3.1, your call of 3 Oct).
  • Moving an open file into a private Folder is refused. Moving a private file out isn't (spec §3.3).
  • Today's spec stores a new comment in the Folder that shows the file, for every app (§6.4, merged today with Leaf's change). The 2 October record says the same for new writes.
  • Your 2 October call "moving a file never changes who can read it" covers the file. Under today's comment rule, moving a private file does change who reads its new comments. B keeps the two calls consistent.
  • Interop's "which Folder does this file write into" already gives the file's own Folder. Only the apps' choice for comments would change under B.
  • Not verified: whether Peek or Ship shows anything per Folder (an unread dot, a Folder feed) that counts comments by where they're stored, and so would move under B. Checked when it's built.
