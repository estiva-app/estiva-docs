How an app finds the Company Folder

Two things you decided live in the workspace's Company Folder: a project filed in no Folder, and the company's own statuses. How does any app, ours or an outside company's, know which Folder that is?

Today

Estiva has five team Folders: Estiva HQ, Ship, Peek, Steer and Leaf. Estiva HQ is the Company Folder only because we call it that. Nothing on the relay says so, and no app's code knows it.

On 29 and 30 Oct you decided, in three records, that a project in no Folder lives in the Company Folder, the one every member reads; that each company keeps its statuses in one file per type there; and that apps find that file "by its type and the admins-only mark, in the Company Folder". The SPEC still says how an app finds the Company Folder "is specified with the move". This SPEC rewrite removes that sentence, so it needs the answer.

Two facts shape it:

  • Only the relay writes what a Folder is. A Folder's name, whether it is public, and its labels are published and signed by the relay. An owner or admin asks the relay to change a name or a label; nobody else can.
  • The relay never makes a Folder by itself. A new workspace starts with none. Every Folder is one somebody made.

Why it reaches beyond this ticket

It is the rule every app and every outside company uses to find the company-wide home: where a project nobody filed goes, where the company's statuses are, and later anything else the whole company shares (labels, priorities, the Company team's #general in the navigation brainstorm). It also decides whether a workspace can be without one. The relay needs the answer too, not only apps: from this rewrite it refuses a change filed in another Folder than its file's, so it must know which Folder an unfiled project's changes belong to.

Mostly two-way. Files never move: a project filed in the Company Folder stays in that Folder whichever way this goes. What is hard to undo is a promise to outside apps. If they are told "there is always one" and we later allow none, each of them breaks on the workspace that has none.

Options

A · Every workspace has one, kept for good recommended

The relay marks one Folder as the company's. A new workspace gets it when it is set up; Estiva's is Estiva HQ, marked once. It can be renamed, but nobody can delete it, archive it, make it private or take the mark off. Apps ask the relay for the Folder with the mark and always get exactly one.

  • Miky and Katerina: nothing changes on screen. Estiva HQ's menu no longer offers Delete or Archive.
  • Outside company: one question to the relay, one answer, in every workspace. It never has to handle "none".
  • Locks in: the Company Folder is part of the protocol. If the navigation rework makes "Company" a team, this Folder is the obvious place it starts from.
  • What could go wrong: an admin who wants to reorganise cannot get rid of it, only rename it. A workspace that never wanted a company-wide space still has one (it can sit empty). In a Folder shared with a partner company, the mark of the partner's relay must not count as ours: an app trusts only the mark its own workspace's relay signed.

B · The owner picks it, and can move it

An owner or admin marks any Folder as the company's in settings, and can move the mark to another Folder later. The relay keeps at most one marked. Until somebody picks, there is none.

  • Miky and Katerina: a "Company Folder" choice in settings. If Miky moves it, projects nobody filed still sit in Estiva HQ, and the company's statuses go back to Ship's defaults until an admin saves them again in the new Folder.
  • Outside company: must handle "none picked" (where does a new unfiled project go?) and the mark moving under it.
  • Locks in: flexibility nobody has asked for, paid for by every app's "none" and "moved" cases.
  • What could go wrong: statuses silently revert after a move; a stale tab files a project into the old Company Folder.

C · Do less: no Company Folder

The protocol has no Company Folder. A file in no Folder is just that: it names no Folder, and every member of the workspace reads it. The company's statuses file is such a file. There is nothing to find.

  • Miky and Katerina: Estiva HQ stays an ordinary Folder. Projects filed there stay there; a new project with no Folder shows outside every Folder.
  • Outside company: nothing to look up, but a second kind of home to handle: files with no Folder have no Folder conversation, no Folder listing, and no Folder admins to archive them.
  • Locks in: reverses three Accepted records' "in the Company Folder", and the SPEC's rule that every file names its Folder.
  • What could go wrong: every rule written per Folder (who archives, what a list shows, what a shared Folder carries) needs a "no Folder" case, in every app.

How others do it

  • Slack: every workspace has #general; everyone is in it; it can be renamed, not archived or left. That is A.
  • Microsoft Teams: every team has a General channel that cannot be deleted. A again, per team.
  • Discord: the owner picks a "system channel" and can unset it. That is B; apps that post there must handle "none".
  • NIP-29 (Nostr groups): nothing; every group is equal. Whatever we pick is ours to propose.

Recommendation

A: every workspace has exactly one Company Folder, marked by the relay, kept for good. The things the whole company shares, its statuses today and its unfiled projects, need a home that cannot disappear or move under them, and an outside company's app should get one answer it never has to second-guess. Only the relay signs what a Folder is, so a member cannot make a look-alike. It is what Slack and Teams settled on, and it matches "there is always a Company team" from your navigation brainstorm without deciding that rework.

Checked

  • Nothing marks a Company Folder: the relay's Folder metadata carries id, name, about, public/private, unlisted, restricted, hidden, closed, labels and creator only (buzz nfb-demo-kinds, crates/buzz-db/src/store/channel.rs group_metadata_tags).
  • Only the relay signs Folder metadata (side_effects.rs: discovery events 39000–39002 "signed by the relay keypair"); only an owner or admin may change a Folder's labels (group_state_postgres_tests.rs).
  • The relay makes no Folder at setup (no default channel in buzz-relay or buzz-db).
  • No app knows a Company Folder: Ship, Peek, Leaf and the agent on origin/main mention Estiva HQ only in stories and comments.
  • Three Accepted records say "Company Folder": a-companys-statuses-are-its-own-layer-of-a-types-properties, a-file-can-say-only-admins-write-it-and-the-relay-keeps-to-it, and (from 29 Oct, via SPEC §6.13) a project in no Folder lives there.
  • That every member reads a file with no Folder (option C) is what SPEC §5.2 says; not checked on production today.
  • Slack, Teams and Discord behaviour is from their published help, not re-checked today.
