# An Insight, Journal entry or Risk can be about any file of any app, each app says how its own files roll up, and every app that opens that file shows its items

- Date: 2026-11-16
- Status: Accepted
- Decided by: Miky, in the shaping session of 16 November 2026 for the project "Insights, Journal and Risks". Asked about the items' statuses, he widened the question: "This is definitely not just about Ship. If somebody build a HR app and there is two file types: open position and candidate. Those highlights can be related to that. Insights about position, update on position, risk about certain position… I want to make sure that we are treating this as basic stone of Osnova protocol and broader Intelligence layer (the memory layer)". Shown the brief "Osnova's memory layer" ([page](briefs/highlights-are-osnovas-memory-layer.html)), he took its recommendations: "Yes, all five". Lines marked as Claude's are not his words; his merge of this record accepts them
- Area: Files

## Who it affects

Katerina's 18 August "one search, an All topics switch" and Miky's 8 September
"ditch that idea completely" happened in the Peek topic Universal Navigation,
about no issue, project or Initiative. Under this call, that decision becomes
a Journal entry about the topic itself and shows in the topic, beside her
insight. And a company that builds an HR app gets the same memory on its own
open positions and candidates: an Insight about a position, an Update on it, a
Risk about it, shown on the position in its own app, without building a notes
type of its own beside ours.

## Context

- Insights, Journal entries and Risks are three shared types, each item a file
  of its own
  ([what-a-project-learns-decides-and-worries-about-are-insights-journal-entries-and-risks](what-a-project-learns-decides-and-worries-about-are-insights-journal-entries-and-risks.md)).
- An item is filed in one team and is about an issue, else a project, else an
  Initiative, or is just the team's; "about" is a reference, not a parent
  ([an-item-is-filed-in-a-team-and-is-about-an-issue-a-project-or-an-initiative](an-item-is-filed-in-a-team-and-is-about-an-issue-a-project-or-an-initiative.md)).
  Those three levels are Ship's: no other app's file could be what an item is
  about.
- An app names the types it opens in its own listing
  ([an-app-names-the-types-it-opens-in-its-own-listing](an-app-names-the-types-it-opens-in-its-own-listing.md)),
  and a type is a shared meaning any app extends
  ([a-files-type-is-a-shared-meaning-any-app-extends](a-files-type-is-a-shared-meaning-any-app-extends.md)).
- What intelligence finds lands in its home, and you see it when you go there
  ([intelligence-works-in-the-background-and-reaches-you-only-by-naming-you](intelligence-works-in-the-background-and-reaches-you-only-by-naming-you.md)).
- On 9 September Katerina's highlights were lost: they lived only in Peek's old
  database, which was deleted, and never reached the relay.
- No Insight, Journal entry or Risk is on the relay yet, so this costs nothing
  to change now.

## Decision

- **An item can be about any file of any app**: an issue, a project, a topic,
  a document, or an outside company's own type, such as an open position.
  When it can be about nothing specific, it is still just its team's.
- **Ship's issue, else project, else Initiative is Ship's own case** of this
  rule, and stands for Ship.
- *Claude's:* **each app says in its listing how its own files roll up**, as
  Ship says an issue shows on its project and a project on its Initiative. An
  item is also shown on what its "about" file rolls up to, in the app that
  says so. An HR app may say a candidate rolls up to its position; candidates
  rolling up is Claude's extension of Miky's example.
- **Every app that opens the file an item is about shows its items there.**
  The memory sits where the work is, in every app, and no company needs one
  memory app to have one. For the project that builds this, Ship draws them
  first.
- *Claude's:* **an item about a file the reading app cannot open** shows as a
  plain card with its title and a link to the app that opens that file, found
  in the listings.
- Filing in one team, "about" as a changeable reference, and "where it was
  learned is its sources" stand as
  [an-item-is-filed-in-a-team-and-is-about-an-issue-a-project-or-an-initiative](an-item-is-filed-in-a-team-and-is-about-an-issue-a-project-or-an-initiative.md)
  says.

## Rejected alternatives

- **Only Ship's levels, as merged earlier the same day.** Turned down: an HR
  app could not say "Insight about this position" and would grow its own notes
  type beside ours, the private memory inside one app that the 13 November
  record set out to avoid and that lost Katerina's marks on 9 September.
  Widening later would have been compatible, but apps built meanwhile would
  assume three levels.
- **One memory app**: Ship holds every list, and other apps offer Mark and a
  link into it. Turned down: Ship would become required for any company that
  wants memory, and "not just about Ship" would be undone by the screens.

## Consequences

- Supersedes in part
  [an-item-is-filed-in-a-team-and-is-about-an-issue-a-project-or-an-initiative](an-item-is-filed-in-a-team-and-is-about-an-issue-a-project-or-an-initiative.md):
  its "about an issue, else a project, else an Initiative" becomes "about any
  file of any app, Ship's three levels being Ship's case". Everything else in
  it stands.
- Once items about other apps' files are on the relay, narrowing "about"
  again strands them: it is one-way from then.
- *Claude's, for the SPEC PR:* "about" names any file address (SPEC §6.1, one
  id, one file), and the shape in which a listing names the field its files
  roll up by is left to the SPEC PR the project already owes, with the type
  claim of
  [an-app-names-the-types-it-opens-in-its-own-listing](an-app-names-the-types-it-opens-in-its-own-listing.md).
- Every open of a file reads its items too. That read is not yet measured on
  Miky's workspace; the build measures it as its load cost.
- An app that never draws the lists leaves its files' items in their team's
  list only. An app that declares its roll-up wrongly lists items in the
  wrong place among its own files only.
- A topic's or a document's own lists in Peek and Leaf are allowed; whether the
  first build draws them is the project's scope call.
- Still brought with private teams and notes: an item about a file in a
  private team names that file to the item's readers.
