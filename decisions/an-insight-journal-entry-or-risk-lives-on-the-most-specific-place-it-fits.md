# An Insight, Journal entry or Risk lives on the most specific place it fits, a task, else a project, else an Initiative, and each level shows everything below it

- Date: 2026-11-13
- Status: Accepted
- Decided by: Miky, in the brainstorm session of 13 November 2026: "as specific as possible", on a task, else the project, else the Initiative; items live under the project "the way issues do"; choosing the home is "secondary", with several ways in; written up as the brief "What a project knows" ([page](briefs/highlights-and-what-a-project-knows.html))
- Area: Files

## Who it affects

Katerina finds in Peek that the share dialog confuses people. If an issue for
the share dialog exists, the Insight lives on that issue. If not, it lives on
the project, and if the work has no project yet, on the Initiative it belongs
to. Miky opens the project's Insights and sees hers among those of every issue
in it; on the Initiative he sees those of every project under it.

Nobody has to pick a home with care: an app or an agent suggests one, and
"Mark as highlight" on a message or block may name a task, a project or an
Initiative. The home can be changed later, as an issue is moved between
projects.

## Context

- An item of [what-a-project-learns-decides-and-worries-about-are-insights-journal-entries-and-risks](what-a-project-learns-decides-and-worries-about-are-insights-journal-entries-and-risks.md)
  has one home.
- An issue's project can already change: it is a field of the issue, and Ship
  and the agent move one between projects. Moving re-parents the issue only;
  its conversation stays in the Folder it was filed in.
- A comment, or a file made under another file, is stored with it, so only that
  file's readers read it
  ([what-belongs-to-a-file-is-stored-with-it](what-belongs-to-a-file-is-stored-with-it.md)).
- "Initiative" is the name Miky leans to, on 13 Nov, for today's topics: work
  that spans apps. It waits on Katerina's look at the navigation prototype.

## Decision

- **One home per item, as specific as it fits**: a task (an issue); if no task
  fits, the project; if no project exists yet, the Initiative. This record
  means whatever that top level is finally called.
- **Each level shows everything below it.** A project's Insights, Journal and
  Risks include those on its tasks; an Initiative's include those of its
  projects and their tasks. Rolling up is a way of showing, not a second home.
- **The home is a field and can change**, the way an issue moves between
  projects, and the change is kept in the item's history.
- **Choosing the home is secondary**: an app or an agent suggests it, and a
  person may name it when marking, or change it later.

## Rejected alternatives

- **Several homes per item**: one Insight sits on the issue and on the project,
  or on two projects at once. Turned down: with the roll-up, the project
  already shows what is on its tasks, so several homes would only show items
  twice, and every app would need rules for whose readers may see an item and
  which home's status counts.

## Consequences

- An item is read by its home's readers, like a comment or an issue under its
  project. An item on a task the whole company cannot read stays out of view
  for those who cannot read that task, also when its project shows it.
- Moving an item has the issue's trap: its conversation stays in the Folder it
  was first filed in.
- Showing an Initiative's items means reading every project and task under it;
  its load cost is measured when the build is shaped.
- Where an item lives that fits no task, project or Initiative, such as an
  insight from a team's chat about no project, is not decided here.
