Estiva architecture

As built, 2026-10-23 · the whole suite, as it runs today

Estiva is a set of apps for one team: Peek for chat, Ship for projects and issues, and Leaf for documents. They share one workspace, which is a single relay. Every app reads and writes the same signed events there, so a file made in one app can be found and discussed in the others.

Start with the first map, then look at Objects to see what a person meets. Flow follows one comment from Ship to Peek. Project pages redraw their parts from this page.

Access

Every read and every write is made by someone on the workspace, and every event is signed by the person who sent it. The rows below are the rules the relay, Estiva ID or each reading app enforces; a rule that is decided and still being built names its record and the issue that carries it out. Every Folder is open today, so "whoever can read the Folder" is everyone on the workspace until private Folders exist (SPEC §3.1).

  • Apps have no server of their own. Peek, Ship and Leaf are static builds in an nginx image: peek:Dockerfile:8-14, estiva-ship:Dockerfile:28-30, leaf:Dockerfile:11-13. Peek's old Convex backend is gone (removed 2026-09-25, estiva-docs:ROADMAP.md:124).
  • Sign in and sign. Each app signs in through createEstivaId (peek:src/auth/estivaId.ts:23, estiva-ship:src/auth/estivaId.ts:60, leaf:src/auth/estivaId.ts:1); signing is POST /sign (estiva-foundation:packages/identity/src/signer.ts:127-140). Estiva ID keeps each key encrypted in Postgres (estiva-id:docs/KEY-CUSTODY.md:14-16, README.md:10-12), signs in with passkeys (docs/API.md:39-50) and publishes profiles (src/domain/policy.ts:130-141). SPEC §4.3–4.4.
