Tests that try thousands of inputs

As built, 2026-11-20 · shaped the same day ·Ship project · Goal: a file reads the same in Ship as in Peek and Leaf, and a document or a link comes back as it went in, checked on every change by tests that make up their own inputs. Follows Smoke test after every deploy.

Nothing a person uses changes. The picture to look at first is "Who reads a file's changes": the same changes are read by three pieces of code today, and nothing checks that they agree beyond one recorded set of real events. The project adds tests that make up thousands of histories and compare the three.

M1 also settles two suspected bugs found while shaping: two changes made in the same second are read in the order they arrived, and a file id with a colon in it is cut short. As built, both were real and are fixed: two versions saved in the same second always list the same way, and a file id with a colon no longer drops its creator from it (protocol 0.62.0, interop 0.108.0, conversation 0.43.0).

Objects, Flow and Access are not drawn: the project changes no object, nothing moves between apps or people differently, and nobody's access changes.
