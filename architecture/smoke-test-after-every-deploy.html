Smoke test after every deploy

As built, 2026-11-20 · shaped 2026-11-19 · Ship project · Goal: after every deploy, a change in one app that breaks the app next to it is caught by a run on production, not by Miky or Katerina.

Today the only check after a deploy is the ticket's own, in the app that changed. The project adds one run that signs in to every app as test accounts and walks about ten core flows, half of them one app showing another app's file. Look first at the Map's "After": the run reaches all four apps whichever one was deployed.

As built, the shape held, with five findings. The test has a repository of its own, the public estiva-app/smoke: one command, node run.mjs, and the list of core flows beside it, CORE-FLOWS.md. A failed step's screenshot shows production as the test accounts see it, so it goes to the private estiva-app/smoke-runs, and the comment on the pull request links it. Each app says its version at https://<app>.estiva.app/version.json, never cached, and the run waits there for the merge commit before its first step. The relay says its version only from the server: /land waits for a relay change from the box, then runs the test without a version to wait for. A run after a relay change has not happened yet; on Miky's call it is shown on the next relay merge. All ten flows take about ten minutes (617 s on 19 Nov), about five of them waiting so each account stays inside the relay's limit, as Smoke Test 1 and Smoke Test 2 in the QA team. "The version before" is a rebuild only for Peek, Ship and Leaf, served to the test's browser alone at the real address. For Estiva ID and the relay it is the last run on this machine. A step that names an open bug is reported as known while that bug is open; a check that fails only sometimes is run again and filed, never marked known (Miky, 19 Nov). The Map, the Flow and Checked are redrawn to match.
