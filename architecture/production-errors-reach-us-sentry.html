Production errors reach us

Shaped, 2026-11-17 · Ship project · Goal: when an app or a server breaks on production, we know from the system itself, not because Miky or Katerina told us.

Today nothing reports an error: a crash is seen only by the person it happens to. This project adds one small reporter to every app and both servers. It sends a short report to Sentry, built from a fixed list of fields, and Claude reads Sentry at set moments. Look at the Map first, then at what a report may contain.

A report may contain: the app and its version; the kind of error and where in the code it broke; one of our own fixed sentences or the relay's reason code; the kind of screen (never its address); the last few steps before the error, as kinds of screen and our own named actions; the browser; the person's public key; whether it is a person, a QA account or an agent.Miky, in Sentry. Claude, reading only. Sentry the company, as the host.Nobody. Sentry deletes it after 30 days.The reporter, in the person's own browser, before anything is sent. Tested by planting text and reading the bytes that leave.
A report never contains: message or document text, titles, file names, page addresses, what was clicked, console lines, request contents. An error's own wording is sent only with quoted text removed.Nobody outside the browser.—The same reporter and the same test.
The address the apps send reports to. It is public, like the apps' code.Anyone can send to it. Nobody can read with it.Miky can replace it.Sentry.
Where Sentry stores the reports: Frankfurt or Iowa.—Chosen once, when Miky creates the account. It cannot be changed later.Sentry.

Every row is new. The servers follow the same list: the relay and Estiva ID's server report where the code broke, never what an event or a request contained.

Checked

  • No app or server reports errors today: a search of origin/main in peek, ship, leaf, estiva-id and the relay's nfb-demo-kinds branch finds no Sentry or similar library (17 Nov).
  • Peek wraps itself and its panels in the shared "Something went wrong" screen (src/main.tsx, src/layouts/PeekFrame.tsx), which only writes to the console (estiva-ui src/ErrorBoundary.tsx). The same search finds no such wrapper in Ship or Leaf.
  • Estiva ID is a server and sign-in pages in one repo (src/server.ts, web/); the relay is written in Rust and already writes structured logs (tracing in Cargo.toml).
  • The peek, ship, leaf and estiva-id repos are public (gh repo view), so readable stack traces reveal nothing new. The relay's repo is private.
  • Sentry's pages, read 17 Nov: free plan is one user, 5,000 errors a month, 30 days kept; the storage place is fixed at creation; a per-app cap is a paid feature; the standard library also collects console lines, clicks and addresses unless turned off.
  • Not verified: whether a free-plan account can be read by Claude at all (the price list says "API: No", and lists a Claude connector as included). That is milestone 1.
